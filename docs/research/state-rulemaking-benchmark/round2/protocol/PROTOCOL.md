## Rendering ambiguity and semantic scoring

Reuse the frozen field outcomes and strict gate: complete usable output, reference eligibility, every critical field passing its answerability-specific test, and no critical incorrect assertion in the notice-wide audit. Source uncertainty yields `insufficient_reference`, not success. Empty/failed output is operationally unusable, not safe abstention. A present answer that is withheld is a safe miss, not recovered evidence.

Assess the actual scored representation and preserve exact characters. Markup differences matter when they change identity, selection, lifecycle, conditions, or date roles; cosmetic differences alone do not fail. Do not assume `~~` inside an HTML block renders as deletion. Record raw span, source region, markup context, semantic effect, and adjudication rationale. If rendering is used, pin the renderer, extensions, HTML policy and version for all arms before held-out scoring. No renderer shopping after a disagreement. Unresolved decisive ambiguity is `partial_ambiguous`; an unsupported but semantically harmless marker remains a diagnostic. Ordinary Markdown deletion of a substantive temporal condition can fail the extra-assertion audit even if all reference fields pass.

The reviewer sweeps every retained notice for extra or contradictory participation dates, temporal anchors, selected states, lifecycle and withdrawal scope, including facts outside the selected questions. Deduplicate one underlying wrong assertion across affected fields. Record output hash, exact quote and offset/line/JSON-pointer locator, source evidence, criticality, error type, and rationale. Full relevant scope must survive for `not_stated`; keep scope-only failures distinct from positively invented claims.

## Separate normalization and router experiment

Parsing judgments are reviewer-assessed evidence preservation. They do not measure automated normalized-field precision, safe automatic acceptance, or routing performance. Unless actual components are implemented and frozen, report those measures as **not run**, never synthesize them from reviewer answers or an imagined router.

No normalizer or router is currently being run in round two. A later actual normalizer must receive only its assigned parser representation and permitted metadata, not source references or other arms. Freeze its code/model, prompt, schema, evidence-locator rules, versions and settings. Emit typed claims with notice identity, role, literal value, precision, anchor/condition, scope, evidence span and status (`asserted`, `not_stated`, `uncertain`, or `review_required`). Record every emitted critical claim; schema-valid output alone is not correctness. Computed legal deadlines remain outside this trial.

A router must emit a durable `accept`, `escalate`, or `review` decision, reason codes, visible features and stage-specific artifact hashes. Its decision may use only information actually available at that stage. Whole-page gold references, reviewer gates, future parser outputs, and fixture-specific IDs are forbidden routing features. Replay against captured outputs is allowed only with these access restrictions and an explicit simulation label. Summing selected stage times is a cost/latency model, not a measured production run. A post-hoc best-of-four oracle is merely an upper-bound diagnostic.

Independently audit every automatic acceptance against complete source scope and every emitted critical claim, including extras. A false acceptance is an accepted notice containing a wrong, unsupported, missing required critical claim, unresolved decisive ambiguity, unsupported absence, source conflict collapsed to certainty, or invalid evidence support. Report false accepts / all accepted notices; zero accepted means undefined, not 100% precision. Also report correct automatic accepts / all scheduled notices, escalation and review rates, unnecessary review among eligible correct outputs, and the failure types that escaped routing. Review every rejected/escalated notice too so safe refusal cannot hide zero utility.

Claim-level precision is allowed only for an exhaustive machine-emitted claim ledger whose entire denominator was adjudicated; otherwise show sampled counts without a precision claim. Report recall against the fixed determinate reference fields separately. Proposed router promotion requires zero false accepts, valid source-grounded evidence for every accepted critical claim, all source-conflicted cases routed to review, and at least half of reference-eligible held-out notices correctly accepted. Eight notices cannot establish a low deployment error rate. Normalizer/router implementation and inference budgets are a separate phase and are not included in the parsing call cap.
