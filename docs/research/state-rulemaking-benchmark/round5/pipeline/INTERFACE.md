# Round-five native-only interface — early integration contract

Keep `round4.sources.v1` source manifest and the round-four case shape unchanged. The copied source-input schema/contract preserve the required keys, opaque IDs, UTF-8 byte hashes, full-notice/slice/unknown scope and page-map declarations. **Round five processes native channel only**; CLI/runtime must reject fallback/OCR channels rather than silently acquire text. The schema remains transport-compatible; this experiment adds native-only execution enforcement.

Import `pipeline.py`: `propose(text, document_id, scope='full_notice', pdf_pages=1, page_map_known=False, channel='native')`, `validate_manifest(manifest)`, `contained_path(base,root,value)`, and `VERSION` remain compatible. Cases have exactly case_id/source_text/candidate/evidence plus source_id/source_locator. Candidate fields remain field/value/claim/target/role/conditions; DATE is ISO date-only or null; EMAIL exact literal. Every source_text is the entire unmodified notice; no reviewer-selected replacement context.

Candidate traces retain case, issues, soft_issues, hard_issues, emit_case, value_span/context_span/condition_spans, raw_literal, normalized_value, precision and timezone=null. Runtime must use the published module's `SOFT_ISSUES`/`HARD_ISSUES`, treat unknown issues as hard, and independently validate exact spans and request limits. Candidate-specific semantic uncertainty can reach the verifier; actual multi-window/conflict/incomplete-scope/relative or ambiguous date signals stay hard. Reachability means eligible to request verification, never accepted source truth.

`condition_scope_requires_semantic_verification`, `competing_temporal_role_cues`, `submission_role_unverified`, `written_comment_role_unverified`, and email/date role multiplicity are soft. Form association uses written_comment_role_unverified plus a form_association trace flag. `participation_lifecycle_unresolved`, `relative_participation_window_unresolved`, `conditional_deadline_unresolved`, actual multi-notice/window evidence and null date normalization are hard for DATE. Relative/conditional timing does not itself hard-block an independently explicit EMAIL; local route limitations still must be preserved. Formal issue inventory is emitted in ROUTING-POLICY.json before READY; do not retain round-four's blanket hard condition override.

Boundary revision: ordinary demonstratives such as “following address/rule” do not themselves become temporal conditions; clocks and genuine qualifications remain exact evidence with date-only precision, not fabricated UTC. Regulation-subject lifecycle words remain in full source and a separate cue trace, but do not automatically settle the window's lifecycle. Candidate-specific association stays a semantic question. Scope/format limitations do not disappear merely because a verifier is favorable.

No provider calls, OCR, fresh-data reads, labels, application changes or production readiness. Freeze this implementation and runtime policy before new collection. All earlier rounds remain frozen.

Primary contract alignment: DATE claim explicitly asserts an actual unconditional absolute close. Applicable qualifiers are selected within the candidate paragraph/form header; unrelated paragraphs are not copied into candidate.conditions, but remain complete in source_text and qualification_cues. True hearing conditions in a different paragraph are not automatically assigned to a written close. Asserted actual participation lifecycle changes remain hard; hypothetical may/might/could statements remain visible for semantic review.
