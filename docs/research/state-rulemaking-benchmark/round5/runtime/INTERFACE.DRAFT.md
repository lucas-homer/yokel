# Round 5 runtime interface — early integration proposal

Runtime consumes the R4 source/case interfaces, native channel only: `validate_manifest(manifest)`, `contained_path(manifest_dir, source_root, relative_path)`, `propose(text, document_id, scope=..., pdf_pages=..., page_map_known=..., channel="native")`, and `VERSION`. If A versions the manifest schema, its strict validator is authoritative; no labels/expected outcomes may enter the contract. Every emitted case must contain the entire original native notice text and exact value/context/evidence spans. Preserve R4 candidate keys and field names.

Caps: eight documents, 80 Jev POST cases, $0.10 nominal/accounted budget. No OCR/OpenRouter route or credential. PDF byte/hash/page count checks remain; mechanical PDF page count only. One native candidate field judgment per Jev request, four frozen R3 Choice rubrics on jev-1.13.0. Full source text, no clipping; max 30,000 code points, 50,000 serialized case bytes, 20,000 conservatively bounded request input tokens. Research-only terminal outputs retain evaluator-compatible R4 schema, no action-ready result.

## Contract needing A/primary confirmation before READY

Generic lexical occurrences of `if`, `hearing`, `withdrawn`, `extension`, neighboring date/contact, etc. should be semantic signals rather than blanket blockers. Exactness/calendar/scope/size/corruption/provenance and unknown issue codes remain hard blockers. Proposed clearable signals: submission/written-role unknown, condition association, lifecycle association, competing temporal role cues, email/date candidate role resolution. A must publish the precise issue names and candidate construction policy; runtime will pin them explicitly, never clear an arbitrary issue.

The frozen condition rubric requires material qualifications in BOTH `candidate.conditions` and `candidate.claim`, with original scope. A must preserve candidate-associated qualifications verbatim or route unresolved/ambiguous association to review; generic unrelated conditional language must not be added as a candidate qualification. No runtime automatic condition repair. Historic/withdrawn/replaced candidates may be judged to identify wrong roles, but may not become current supported observations if lifecycle is unresolved. True incompatible windows or ambiguous relative/date anchors remain hard review. Multiple candidate resolution requires exactly one distinct all-four-supported value and every alternative positively completed `role=mismatched`; unknown/failed/unprocessed/same-value unresolved alternatives block acceptance. This applies to both fields.

Published dependencies: Python standard library plus bundled pypdf for mechanical original PDF page count; frozen adapter SHA 8a0069d19f0fda7eaeac690c59749029b3ccea71fc07dfc2f8d311d2d872a59e. No installs/builds/provider calls by this child.
