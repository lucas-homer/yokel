# Prepared Firecrawl collection lane

Final status: all twenty frozen inputs have exact Markdown captures, comprising fourteen first provider-attempt successes and six single authorized rate-limit recoveries. Original four pre-job local failures, six rate-limit rejections, and both stop histories remain visible. See canonical-results.json for final capture pointers and FINAL-REPORT.md for counts, usage and timing limitations. RECOVERY-REPORT.md is the historical report at the second stop. Source candidates are untouched.

Live callable tool schema is retained in `live-tool-schema.txt`. Hosted flow: phase one `filePath` plus known MIME/byte count; upload identical local bytes using returned HTTPS method/URL/headers/form instructions; phase two `uploadRef`, `formats=["markdown"]`, `parsers=["pdf"]`, `onlyMainContent=false`, and `pdfOptions.maxPages` equal to that unit's frozen input page count. No hints, JSON extraction, URL-fetch fallback, unsupported mode/blocks/pages flags, or alternate arms. Explicit full-content setting is a pre-run choice to request header/footer preservation. Callable schema exposes no parser-version pin or parse-timeout argument; versions/IDs/usage are recorded only when actually returned.

`capture_harness.mjs` runs inside functions.exec after configuration supplies an immutable freeze path, SHA256 and explicit run authorization. `verify_freeze.py` verifies its checksum, checker-compatible passing corpus record, exact IDs/order, twenty distinct input hashes, byte sizes/page limits and frozen companion hashes where supplied. It refuses existing per-unit results rather than blindly resuming a possibly billed operation. `upload_transfer.py` receives signed instructions through a transient live stdin pipe, validates the local PDF hash and size limit, uploads without echoing URLs/credentials, and retains only a sanitized status/latency receipt. No signed upload instruction file is created.

At most two operational pipelines run concurrently; therefore at most two provider calls can be outstanding globally. Starts follow frozen order. The queue counts failures in operational pipeline completion order, including phase-one/upload failures, stops submitting after three consecutive failures, and retains any already-in-flight result. No automatic timeout retries or other retries are enabled. A pre-job recovery, if warranted, requires inspecting proof of the failure and is not performed blindly by this harness.

Each unit retains phase-one request and sanitized response; upload receipt; sanitized phase-two request with local hash; complete unmodified final tool response; exact UTF-8 Markdown (including terminal-newline state); UTC start/end and measured wall times; actual returned usage/job/version fields; and outcome. An echoed upload credential would be redacted explicitly and recorded as an exception to unmodified response retention. Unknown credits/version/job identifiers remain null. Exact Markdown capture uses a local pipe helper to avoid apply_patch adding a newline. Final `results.json` records completion order, operational denominator and skipped units.

Node syntax checks passed. Remaining execution dependencies are the parent's immutable freeze, compatible manifest fields and explicit run message. No vendor request has been used to test upload-instruction or response-shape assumptions; actual returned instructions will be inspected before the first upload. A successful nonempty Markdown capture is only an operational success, not evidence preservation or semantic accuracy.
