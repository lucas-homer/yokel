# Prepared REST continuation

The runner is Python standard-library only. Preparation and dry-run make no provider requests, access no key, install nothing, and create no execution captures. Only the 28 pairs in execution-dashboard-1/resume-state.json are eligible. The 12 completed pairs are checked against retained artifacts and excluded. Every input is the existing staged PDF checked against frozen hash and byte count. All frozen companion files are checked before running.

Run `python3 run_llama_api.py artifacts` for the offline plan. The default is always dry-run. Execute later on the authorized Mini with the resolved environment key, explicit project and documented interface acknowledgement:

```sh
PYTHON_BIN=/Users/home/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 \
sh run_llama_api_with_1password.sh \
  'op://Private/LlamaParse API Key/credential' \
  artifacts --execute --project-id VERIFIED_PROJECT_ID --ack-api-v2-differences \
  --max-new-jobs 1 --max-run-seconds 300
```

The wrapper passes a non-secret field reference to `op run`; the resolved key exists only in the runner environment. It never calls `op read`, writes a secret file, or installs the CLI. The item uses concealed field `credential`, not `password`. [1Password documentation](https://www.1password.dev/cli/secrets-scripts) documents environment injection with `op run`.

The supported endpoints are multipart `POST /api/v1/beta/files` with purpose=parse; JSON `POST /api/v2/parse` using file_id; `GET /api/v2/parse/{job_id}` with repeated expand values; and paginated `GET /api/v2/parse` for reconciliation. The REST create response has top-level id/status; polling uses job.id/job.status. [REST guide](https://developers.llamaindex.ai/llamaparse/parse/guides/api-reference/) and [upload reference](https://developers.llamaindex.ai/reference/resources/files/methods/create/) establish these shapes.

Configuration uses tier=agentic or agentic_plus, version=latest, disable_cache=false; processing_options.cost_optimizer.enable=false and ignore.ignore_text_in_image=false; output_options.images_to_save=[screenshot], markdown.inline_images=false, tables.output_tables_as_markdown=false, tables.merge_continued_tables=false, and spatial_text.preserve_very_small_text=false. No custom_prompt, target pages, crop, confidence upgrade, extraction schema or expected-answer hints are sent. Reconciliation tags are non-secret job metadata, not parsing prompts. These are fields in the [create reference](https://developers.llamaindex.ai/reference/resources/parsing/methods/create/).

This is a recorded interface change, not an assertion that dashboard and v2 configuration are identical. No documented v2 equivalents were verified for legacy high_res_ocr=true or hide_headers/hide_footers=false; those unsupported fields are omitted. Standard confidence is left at its default. No fixed dated version is substituted for latest. Full Markdown is requested directly with expand=markdown_full, alongside markdown/items/job_metadata/usage; the runner does not reconstruct the scoreable Markdown or rescue it with JSON. The response and output.json remain supplementary to exact output.md. [Retrieval guide](https://developers.llamaindex.ai/llamaparse/parse/guides/retrieving-results/) documents the full-document field.

A06/A07 candidate file IDs come from their completed Agentic dashboard captures. Reuse requires accessible file metadata in the explicitly selected project and a transient content download whose SHA256 matches the staged frozen bytes. Every newly uploaded file receives the same verification. A remote mismatch, inaccessible ID, or expired file pauses execution; there is no automatic replacement. [File-content reference](https://developers.llamaindex.ai/reference/resources/files/methods/content/) documents the signed-download URL. URLs remain transient, receive no API Authorization header, and are never retained.

The new execution-api-1 lane contains an atomically persisted state.json, durable intent tokens/job IDs, per-request HTTP receipts and raw response bytes, exact whole-document Markdown, expanded JSON and capture metadata. The old dashboard/connector artifacts are never changed. HTTP receipts timestamp actual dispatch separately from receipt; billing fields are stored only when returned. Raw bodies remain exact unless key or transient-URL exclusion requires explicit redaction; redaction exceptions are recorded. The signed-file download is hashed in memory and not saved. A process lock prevents two runner instances; cache-enabled jobs still receive their durable job IDs.

At most two accepted parse jobs are active. Three consecutive terminal operational failures latch a stop; already accepted jobs are still polled and retained. Empty/missing Markdown or failed pages are operational failures. An uncertain POST or read failure conservatively pauses immediately, preserving known accepted IDs for resume. Neither upload nor parse POST is automatically retried. After an interrupted submit, the runner pages jobs created since its recorded dispatch intent and matches the durable token, tier and input hash. Exactly one match resumes polling; zero/multiple matches pause. Listing's metadata is not searchable server-side; matching is local. [Job-list reference](https://developers.llamaindex.ai/reference/resources/parsing/methods/list/) documents pagination and returned metadata. An uncertain upload without a returned file ID requires external file reconciliation; the runner refuses another upload.

Resume with the same command and project. `--execute --reconcile-only` performs read-only job reconciliation/polling, never uploads/submits. It requires an existing state file. The latched stop is not automatically reset. No option authorizes retrying an uncertain or failed parse. Project/key account access, candidate file accessibility and the v2 interface amendment still need primary verification before live execution. Preparation made no authenticated request.

The example is a one-job pilot (A06 Agentic Plus), with the full immutable28-job plan retained. `--max-new-jobs` caps only new POSTs this invocation; existing jobs are reconciled/polled first. Pairs drain completely before another pair starts. `--max-run-seconds` bounds local execution; network requests each have a45-second timeout, and any already accepted job IDs remain durable at budget exit or interruption. No backend job is declared failed merely because the local invocation ends. Use the bundled Python shown above: primary verified its TLS trust; do not disable certificate verification. `--attach-file FIXTURE_ID=FILE_ID` plus `--reconcile-only` can resolve an interrupted upload by downloading and checking the candidate bytes without another upload.

Failure sequencing uses the order terminal results are observed by this runner, not an invented provider-completion order. Socket timeouts are45 seconds; the local invocation budget is checked between scheduling/polling operations and immediately before parse submission. A budget exit preserves accepted jobs for resume.
