# Round6 participation record — runtime integration contract

Status: v1 callable contract; development validation in progress. No provider calls here. Prior rounds immutable. Native full text only, passed unchanged. This round intentionally replaces the singleton DATE/EMAIL candidate transport; do not adapt it back to a single winner.

Import `pipeline.py` (stdlib only). Callable interfaces:

- `make_source(text, document_id, *, scope='full_notice', channel='native', pdf_pages=1, page_map_known=False)` -> source descriptor including full `source_text`, SHA256, and declared scope/page metadata. No discovery or provider calls.
- `inventory_request(source)` -> `{task, system, user, response_schema}`. Runtime sends this to the stronger inventory model before any record exists, retaining raw output and provider metadata. Inputs include ONLY source descriptor/full text and inventory instructions/schema: no proposed candidates, record, labels, gold, or prior outputs.
- `assemble(source, inventory)` -> `{schema_version, pipeline_version, document_id, source, inventory_sha256, inventory, record, validation, production_eligible, action_ready}`. It validates strict shapes, exact quote resolution, source hash, reference integrity, local IDs and typed association structure, then projects the inventory without dropping items. Invalid inputs return a validation-failed envelope with `record: null`; no truncation, fuzzy quote repair, inferred date, or automatic condition removal. `validation.valid` is structural/evidence validity, **not source correctness/completeness**.
- `verification_payload(source, assembled)` -> `{payload, payload_sha256}`: canonical common fullsource+record payload. Reject invalid or caller-mutated assembly. Every inventory fact is in record, with resolved exact spans; retain raw inventory separately rather than duplicating it in the verifier payload.
- `verification_request(source, assembled)` -> `{task, system, user, response_schema, payload, payload_sha256}` for the **generative stronger verifier**. It must audit omissions independently of inventory coverage claims, and can return missing-item citations.
- `jev_question_specs()` -> five direct bounded probes: support, association, requirements, source_identity, completeness. Runtime uses its non-generative Jev transport with the exact common payload for each probe. Jev does **not** emit arbitrary missing-item spans or the stronger-verdict JSON. Model-specific adapters and outputs are deliberately different; source+record evidence and dimensions are common. Preserve abstentions/errors; confidence policy belongs to preregistered runtime/evaluation contract, not this module.
- `validate_verdict(source, assembled, verdict)` -> validation result with exact resolved evidence, for the stronger generative verifier only. Schema/evidence checks only. Never turns a positive judgment into production readiness.

Inventory v1 shape (schema in `inventory.schema.json`):

```
{
 schema_version: 'round6.source_inventory.v1', document_id, source_text_sha256,
 coverage: {status: 'claimed_complete'|'uncertain', rationale, evidence: [span]},
 events: [{id, phase, description, timing: [{id, kind, role, dependency_relation, anchor_event_ids:[id], condition_requirement_ids:[id], raw, value, evidence:[selector]}], evidence:[span]}],
 routes: [{id, channel, role, literal, event_ids:[id], alternative_group: string|null, association:'source_resolved'|'uncertain', evidence:[span]}],
 requirements: [{id, kind, modality, semantic_class, text, event_ids:[id], route_ids:[id], association, evidence:[span]}],
 identities: [{id, kind, literal, relation:'canonical'|'reference'|'unresolved', event_ids:[id], evidence:[span]}],
 uncertainties: [{id, kind, description, event_ids:[id], route_ids:[id], requirement_ids:[id], identity_ids:[id], evidence:[span]}]
}
```

All arrays required, including empty arrays. **Model evidence selector** is `{quote:str, occurrence:int|null, context:str|null}`. Quotes/context must match exact raw source, including newlines. Unique quotes use both null. Repeated quotes require an explicit 1-based exact-match occurrence or a unique exact context containing the quote once; conflicting selectors fail closed. Assembly resolves each selector to `{start:int,end:int,quote:str}` with Unicode end-exclusive offsets. No model offset arithmetic, whitespace repair or fuzzy matching. Every fact needs evidence. Requirements can be document-level (both association arrays empty) and must remain visible. `alternative_group` supports multiple valid route members: alternatives are not contradictions. Separate initial/reply/response/hearing/hearing-intent events; publication delay/reference/format/timing are requirements bound to their applicable event/route. Identity ambiguity remains visible rather than selecting one docket. Absolute DATE timing is ISO date-only with an explicitly printed complete date in evidence; clocks/relative rules stay raw with `value:null`. No UTC/year inference.

Record preserves every inventory fact and association. Inventory coverage is a model claim, not proven source completeness. Runtime MUST retain source + raw inventory + assembled envelope + both raw verdicts; never mark absent items source-not-stated from the record alone. Verification output reports support, role/association, requirement preservation, source identity, and completeness separately, including missing source items with exact spans. Runtime enforces size and budgets without clipping full source. All results remain research shadow, `action_ready:false` / `production_eligible:false`.

The source-inventory call uses a generative model (exact model selected/pinned by runtime within the $2 total experiment budget); the stronger verifier may be a different model or the same model family, but separate calls and prompts. Jev and stronger verification receive the same payload; inventory-model self-review is a methodological limitation to report. Freeze pipeline/schema/prompts with runtime before collecting fresh sources. Development regressions use round5 only and are not an accuracy evaluation.

Semantic boundary: an explicitly conditional/relative event can be fully represented, including its unresolved absolute date, without failing structural assembly. It is not an unconditional scalar projection. `review_reasons` flag only inventory-claimed uncertainty, unknown timing, uncertain association or identity—not relative/conditional timing by itself. A valid assembly is never semantic acceptance or verified absence. All records remain not action-ready. Evaluation owner defines the final paired acceptance rule before freeze.

Strong verdict schema: `round6.record_verdict.v1`, document_id and paired payload hash, completeness `{label:complete|incomplete|uncertain,reason,evidence}`, source_identity `{label:resolved|unresolved|contradicted|uncertain,reason,evidence}`, assessments for exactly all event/timing/route/requirement/identity/uncertainty IDs (`support`, `association`, `requirements`, reason, evidence), missing_items with kind/description/evidence, contradictions with existing item_ids/description/evidence. All evidence uses quote selectors, resolved by validation. Full schema files are authoritative for enums/bounds. `complete` plus nonempty missing_items fails structural validation; positive model judgments still need independent source scoring.

Typed-field alignment (required before runtime integration): timing `role` = opens/closes/hearing_start/hearing_end/hearing_intent_cutoff/publication/other/unknown. `dependency_relation` = none/before/after/upon/during/unless/other/uncertain; `anchor_event_ids` and `condition_requirement_ids` are validated references. Relative/conditional timing requires a dependency relation and binding, or explicit uncertain association. Source posting may be a `publication` event with no absolute date. Requirement `modality` = mandatory/optional/conditional/informational/unclear; `semantic_class` = instruction/disclosure/other. These are model-extracted semantic claims, not inferred from prose by assembly. No dependency arithmetic or date inference. Unknown modality/temporal association stays explicit and requires review.

`development-ky-large.json` contains unmodified round5 eight-page native KY text, a hand-authored development inventory, assembled record, and common paired payload for **offline runtime admission testing**. It is not a paid extraction result or accuracy datum. Run `PYTHONDONTWRITEBYTECODE=1 python3 development_fixtures.py --output development-ky-large.json` to regenerate and print sizes. Common payload contains source once plus all normalized inventory facts/coverage/uncertainties; raw inventory is retained in the artifact, not duplicated into verifier input. Admission must measure actual model-specific requests, not infer a provider limit from an internal byte heuristic.

Assembled `record.schema_version` is `round6.participation_record.v1`; `record.schema.json` specifies the normalized evidence-spans shape. Raw inventory remains `round6.source_inventory.v1` with quote selectors. Assembly retains all items and changes only evidence resolution and the transport version.

Bounds: full native source at most 30,000 Unicode codepoints; at most 200 aggregate fact IDs across events, nested timing, routes, requirements, identities and uncertainties. Per-array/string schema bounds also apply. Exceeding limits fails closed without dropping facts. These are experiment design caps, not claims about provider limits; runtime caps/reservations must accommodate them or explicitly record failures.

Prefreeze review fix: explicit `phase:unknown`, route `role:unknown` or `channel:unknown` remain structurally representable but emit `event_phase_unresolved`, `route_role_unresolved`, or `route_channel_unresolved` in review_reasons. Favorable semantic judgments must not erase those extraction uncertainties. `other` is a distinct resolved classification; explicit conditional/relative dependencies alone still do not trigger an unresolved-extraction guard.

Prefreeze prompt alignment (1.0.2): inventory and stronger verification explicitly cover instruction modality; disclosure/public-posting/publication/confidentiality scope and exceptions; and ancillary accessibility/copies/query contacts with actual functions/roles and participation limitations. Jev retains five direct probes with the same universe named within association, preservation and completeness. Ancillary routes use information_contact/other, with a linked informational other-kind requirement describing function when needed; they remain in completeness but are not silently promoted to direct submission. Shared address/functions retain distinct roles. Disclosures are checked separately from mandatory submission instructions. Runtime admission must use final prompt/probe wording, not only common-payload size.
