# Offline evaluator boundary — v1

Evaluator-only data. Nothing in this directory is runtime input. The proposer/runtime artifacts remain frozen. This is infrastructure, not labeling; no fresh sources or runtime results were inspected to develop it.

API: `evaluate(manifest, labels, terminal_documents, acceptance_audits, stage_states=None)` returns JSON counts, field coverage, scheduled-document accounting and completeness. `manifest` is the frozen `round4.sources.v1` manifest; its actual document count is the denominator, never a hardcoded twelve. `terminal_documents` contains only final `shadow-observations.json` objects keyed by document ID; `shadow_status == "text_supported"` is terminal acceptance. Provisional native/fallback model results provide no recovery credit. Missing terminal output is partial if stage artifacts exist, otherwise not_started.

`labels` shape is `{"schema_version":"round4.evaluation.labels.v1","documents":[...]}`. Each notice preserves all keys required by `../protocol/source-label-contract.json`, using concrete `fields` rows for `source_states_for_both_fields`; `required_field_values` lists source-resolvable in-scope field IDs. A notice record includes:

- `opaque_document_id`, `original_pdf_sha256`, `retained_pdf_sha256`, `official_url`, `physical_page_mapping`, `all_source_pages_viewed`, `complete_notice_scope`, `source_states_for_both_fields` (DATE/EMAIL arrays of source-state strings), `required_field_values`, `scan_degradation_basis`, `reviewer_identity`, `reviewed_at_utc`, and `fields`.
- A field row includes `field_id`, `field_type` (`DATE` or `EMAIL`), `source_state`, `raw_literal`, `page_region`, `exact_source_quote`, `role`, `conditions` (source qualification strings), `supported_scope` (boolean), `distinct_value_group`, `uncertainty_reason_if_any`, `normalized_value` (ISO YYYY-MM-DD or exact email, otherwise null), and `source_precision` (`date`, `literal_email`, or `unsupported`). These last two are evaluator extensions, derived from independently viewed source, never parser text.
- Canonical roles: `written_comment_close` and `written_comment_submission_email`. Use protocol source states unchanged. Repeat mentions share a group; materially distinct applicable values/conditions use distinct groups. Eligible instances are present_in_scope + supported_scope + canonical role + explicit source normalization. Absence/out-of-scope/uncertain roles are not eligible positives.

`acceptance_audits` shape is `{"schema_version":"round4.evaluation.audits.v1","audits":[...]}`. Each terminal candidate audit supplies `document_id`, `case_id`, `channel`, `claim_group` (same only for semantically identical terminal claims, including role/conditions/precision), `source_field_id` (nullable), `source_value` (`correct`, `incorrect`, `unknown`), `role` (`matched`, `mismatched`, `unknown`), `conditions` (`preserved`, `lost_or_changed`, `unknown`), `precision` (`date_only`, `exact_literal`, `mismatched`, `unknown`), `scope` (`matched`, `out_of_scope`, `unknown`), `reviewer_identity`, and `basis`.

Source labels must be frozen independently before runtime outputs. Audits are a **separate postrun review of actual terminal claims against that frozen truth and source images**. They cannot change source labels or runtime dispositions. Exact normalized value equality alone cannot establish correct role/conditions; every terminal accepted claim requires a source audit. Missing/unknown audits are unauditable unsafe acceptance, not assumed correct. DATE requires date-only precision; EMAIL requires literal exactness (including local part/case). Audited source matches reference a real eligible field ID. Unresolved source roles accepted as settled are counted separately and unsafe.

CLI: `python3 evaluate.py --manifest MANIFEST --labels SOURCE_LABELS --audits ACCEPTANCE_AUDITS --run RUN_DIRECTORY --output NEW_REPORT_JSON`. It reads only the manifest, evaluator labels/audits and terminal files plus mechanical stage-file existence. It does not read PDFs, parser text, provider bodies or intermediate acceptance verdicts. Missing labels remain visible and make coverage/completeness provisional; they never shrink the scheduled-notice denominator. The evaluator writes a new report and never changes runtime outputs.

This adapter deliberately leaves original-source candidate recall, faithful-parse recall, proposal normalization assessment and parser-text judgment accuracy unmeasured: those require independent stage-specific audits, not terminal-only inference. Runtime costs are not inferred from reservations. The report covers final source-audited field recovery, unsafe/conflict acceptance, unsupported abstention, document completeness and scheduled-stage accounting.

Audit deduplication uses document + field type + independently assigned `claim_group`; native/fallback repeat mentions share it only when their material claims agree. Unknown unaudited claims cannot be safely deduplicated and remain separate unsafe rows. A correct fact does not erase an unsafe duplicate claim.

## Executable review corrections — E01/E02/E03

Under the frozen runtime there is no whole-notice/absence-verification capability. Every `action_ready=true` or ready/complete declaration is therefore unsupported runtime readiness, even if postrun source audit proves all required fields/absences. Gold source completeness remains a separate evaluator result; no ready declaration keeps the metric denominator zero/null.

Unsupported abstention is scored per source distinct-value group. A positively source-audited, role/condition/precision-preserving different value group does not suppress abstention credit. A same-group accepted claim suppresses credit. Unmapped/unknown or materially unverified accepted claims conservatively block credit for the affected field type; a missing terminal document receives none.

Audited acceptance groups must have identical serialized candidate values and source fact/condition group identity. Material differences raise `ValueError` rather than shrink the acceptance denominator. Repeated native/fallback mentions of the same source fact can still deduplicate; unsafe repeated claims still taint their group. No audit/input schema changed for these corrections.
