# Bounded offline semantic audit input

This contract is normative alongside SPEC.md. It adds a local reviewed audit file and bounded aggregation rules only. It does not implement semantic extraction, a signing or authority service, a generic evaluation framework, or provider execution. A hash binds bytes; it does not establish that an assertion is true. The reviewer must inspect source scope, mappings, and every field judgment. A plausible but falsely approved judgment cannot be disproved by this contract alone.

## Exact inputs and review boundary

The aggregator takes (1) exact source text, (2) unchanged R7 record, (3) one private object conforming to `semantic-audit-input.schema.json`, and (4) the local review file conforming to `offline-audit-review.schema.json`. Missing audit or review file means `unverified`. These are evaluator inputs, never provider inputs. Strict JSON parsing rejects duplicate keys at every depth, trailing data and nonstandard numbers in all four JSON artifacts.

For this bounded contract, canonical JSON means UTF-8 `json.dumps(value, sort_keys=True, separators=(',', ':'), ensure_ascii=False, allow_nan=False)` with no trailing newline; arrays retain order. The underlying R7 and audit fields use strings, integers, booleans and null, not floats. `source_text_sha256` hashes exact UTF-8 source bytes, without normalization. `record_sha256` hashes the entire canonical R7 record, including evidence and coverage. `source_reference_sha256` hashes canonical `source_reference`. The review entry's `audit_sha256` hashes the entire canonical audit object, not the containing fixture-suite file. READY pins exact artifact file bytes separately.

The review file must contain exactly one matching audit_id entry with all four hash bindings equal to the supplied objects. Duplicate review IDs are invalid. A usable entry has decision `approved`, nonempty primary_reviewer and independent_reviewer names/identifiers, distinct from one another and the audit provenance author, and a substantive review_note recording source-only scope and post-candidate claim/mapping review. `pending`, `rejected`, missing endorsements or stale bindings yield `unverified`. Reviewer identifiers document workflow; they are not authentication. This small local artifact is controlled by the primary/reviewer workflow, never synthesized by a provider, the aggregator or candidate data. No command-line `assert_complete`, `trusted=true`, fixture-ID shortcut or runtime auto-approval is allowed. Approval must be recorded only after the actual review; filling in strings is not a substitute for review.

All ten checked-in review entries are pending. No claim here says independent review has already occurred. The primary may record review outcomes in a separately assigned implementation area after the barrier; this proposal does not authorize the implementation agent to approve its own audit. A test may use an explicitly isolated test review fixture approved at that barrier; test setup must not alter production/research review decisions or expose a bypass in the aggregator.

## Source obligations and scope

`source_reference` contains document/source bindings, origin, scope and an exhaustive source-first unit list. Each unit has an ID, category, assertion, exact source evidence and required_source_unit_ids. Source units come from the source-only review, not the candidate record or verifier verdict. The synthetic examples were authored as development annotations and are disclosed as such; real research requires an independently frozen source-only reference. Record IDs cannot create, remove, or define the source universe.

Scope status is `complete`, `partial` or `unknown`. Complete requires reviewed_start=0, reviewed_end=the exact source string's Unicode code-point length, no exclusions, and no unresolved_questions. Its definition must encompass all participation-related identities, facts, events, timing, endpoints, requirements/modality/applicability, relationships, ancillary contacts and disclosures present in the supplied notice. Empty categories are allowed when absent in the source. A complete textual range alone does not establish semantic scope: the reviewer must attest that the unit universe covers it. Real notice attachments, images or links required to understand participation cannot silently be excluded while claiming whole-notice completeness; missing necessary source material means partial/unknown. R9 does not ingest external material or replace the frozen image-reference protocol.

There is exactly one source_dispositions row for every source unit, with no extras or duplicates. Dispositions are `matched`, `mismatched`, `omitted`, `unknown`. Matched requires nonempty operative record pointers, corresponding supported claim checks, and every required source unit matched. Mismatched covers partial or changed recovery; omitted has no operative assertion and empty semantic pointers/claim IDs; unknown preserves unresolved identity, association, modality or applicability. All required-unit references must resolve, without self-dependency or dependency cycles. A locally supported phone subgroup does not discharge the full source alternative-group unit. A dependency defect cannot be hidden by labeling its parent matched: that inconsistent audit is unverified.

Source evidence has 0<=start<end<=source length and exact code-point slice equality with quote. Evidence validates location, not interpretation. `semantic_record_pointers` are RFC6901 pointers to the field inventory below, never evidence, source text, IDs or coverage. Every listed pointer must resolve and correspond exactly to its listed candidate_claim_id; ordering is irrelevant. Each matched source row's claim checks must link back to that source unit. A claim may link to multiple units and a unit to multiple fields.

## Candidate checks and exhaustive field coverage

`candidate_claim_checks` checks the other direction: every normalized semantic field, including unsupported additions that have no source unit. Claim IDs and record pointers are each unique. A source unit does not need a candidate ID. Each row has its exact pointer, canonical value_sha256, supported/unsupported/unknown disposition, source_unit_ids and a review basis. All source references must resolve. A nonempty positive assertion labeled supported requires at least one source unit and a source-grounded basis; unsupported additions may have zero source units. A null or empty local field may be supported as asserting no positive fact, but cannot discharge a source obligation.

The exact inventory algorithm `r7-semantic-fields-v1` visits every object in events, routes, requirements, identities, uncertainties and alternative_groups in record array order. For each object it excludes only `id` and `evidence`; recursively visits each nested timing/components item instead of treating that container as a field; and emits one pointer for every other present field, including empty/null fields and complete relationship arrays. Arrays such as route_ids are reviewed as whole fields, not sampled members. Optional fields absent from the record have no emitted pointer; their missing source assertions are detected by source obligations. Empty timing/components arrays have no nested fields. A schema extension must receive separate review; unrecognized structure is not silently ignored. The unchanged R7 record schema must pass first.

A compound text field is a single bounded review unit: supported means **all** its assertions, qualifications and roles are source-supported. Checking only one sentence or keyword is insufficient. If part is false, mark unsupported; if support is unresolved, mark unknown. This is exhaustive field review, not a claim that atomic proposition extraction has been automated. `claim_coverage.status` must be complete, unreviewed_pointers empty, and the row-pointer set exactly equal to the computed field inventory. Missing/extra rows, invalid hashes or pointers invalidate the audit and yield unverified; the status flag alone cannot bypass enumeration.

Top-level schema_version, document_id and source_text_sha256 are checked as bindings, not propositions. Item IDs are checked structurally. Evidence offsets/quotes are checked independently. Coverage.status is a derived extractor claim: after aggregation, claimed_complete is corroborated only by complete_supported, contradicted by not_complete, and unverified by unverified. Coverage.rationale has no operative authority and cannot repair a source omission; it is never counted as a successful recovery or supporting claim check. This explicit partition covers every record field without making coverage evidence for itself.

## Deterministic result and precedence

Return a structured result with `semantic_status` in `complete_supported`, `not_complete`, `unverified`; `complete_supported` boolean; `review_required` boolean; and a list of diagnostic codes. These are outputs only, never audit inputs. The aggregator may also report known defects when the overall result is unverified.

1. Missing/malformed/unapproved/stale-bound input, invalid evidence, inconsistent mappings, failed exact coverage or incomplete/unknown source or claim scope: unverified, complete_supported=false, review_required=true.
2. Otherwise any unknown source disposition, unknown candidate check, or unresolved guard: unverified, false, true. Known defects may coexist; unknown never becomes a pass or disappears behind a negative label.
3. Otherwise any source mismatched/omitted or candidate unsupported: not_complete, false, true.
4. Only otherwise (all units matched, closure satisfied, every semantic field supported, complete reviewed scope and no guard): complete_supported, true, false **for this offline semantic gate only**. Source units and candidate checks must be nonempty. This never changes production_eligible=false or action_ready=false, and never overrides response/record validation or other host review reasons.

Required independent guards: any R7 uncertainty object, unclear requirement modality, uncertain route/requirement/group association, unknown route channel, unresolved identity relation, or existing host acceptance guard blocks completeness even if audit rows say supported. Use the existing R7 enum meanings; uncertainty about an enum's meaning is unverified, not a novel positive interpretation. Missing source mappings, candidate checks or review approval cannot fall back to the model's completeness label. There is no semantics-from-schema shortcut.

Diagnostic code families are audit_missing, audit_invalid, audit_unapproved, binding_mismatch, source_scope_incomplete, claim_scope_incomplete, source_set_mismatch, claim_set_mismatch, pointer_or_evidence_invalid, dependency_invalid, mapping_inconsistent, semantic_unknown, semantic_defect, and acceptance_guard. Multiple codes may apply; collect them without dropping known defects. Codes do not themselves adjudicate meaning.

## Concrete development mapping and limits

`development-audit-inputs.json` contains ten proposed audit objects corresponding one-for-one to the existing development variants. They enumerate 44 source disposition rows and 214 semantic field checks. `development-audit-mapping.json` provides fixture/variant/audit IDs, canonical audit hashes, row counts and conditional test outcomes. `offline-audit-review.json` deliberately records pending decisions, so all ten currently yield unverified. If independently reviewed and approved without semantic edits, the conditional expectations are three complete_supported, five not_complete and two unverified. The older whole_notice_complete_eligible booleans mean proposed synthetic expectations; they do not override these review requirements.

The mapping fixtures make aggregation and fail-closed behavior testable. They do not prove general semantic accuracy or automated discovery. The manually proposed field checks must be reviewed, especially compound text, local subgroup support, and null/empty values. Source/record hashes and complete row sets detect substitution and omission; they cannot prove truthful adjudication. No old source labels, observations, provider requests or record fixtures have been changed by this addition.
