# R9 exact-ID and completeness protocol — review candidate

This bounded offline design changes the research response contract and adds development regressions. It does not authorize implementation, paid calls, new source collection or a production change. Primary and an independent reviewer must approve this specification and the fixture oracle before implementation starts. Existing R7 record/verdict shapes and all R8 sources, labels, outputs and audits remain immutable.

## Problem and scope

The8192-token diagnostic returned all70 requested items plus an extra `coverage` assessment. It finished normally but failed exact-ID validation. Its global complete label also missed evidence-only repeal/recreation detail and the absent full Zoom/phone alternative relationship, and excused unclear modality as preserved. These are two different failures: response-contract membership and semantic completeness. Enforcing membership does not solve semantics. A bigger cap is not the proposed remedy.

## Exact response schedule and schema

For each candidate record, enumerate existing R7 array items across events, routes, requirements, identities, uncertainties and alternative_groups; include every nested event timing and route component. Exclude coverage and evidence objects. Validate global ID uniqueness before set conversion. Reject empty/reserved `coverage` IDs, collisions, empty schedules and schedules over1000; do not rename, trim or silently deduplicate. Those are research preflight failures, not source absence.

Create the sorted unique ID list and exact canonical record/payload bindings. Use a minimal wire-only response adaptation: `round9.exact-id.record_verdict.v1` replaces the assessments array with an object keyed by every expected ID. For each expected ID, declare the existing assessment-value schema with item_id omitted; require every expected property and additionalProperties:false. The key supplies identity, avoiding duplicated key/value IDs. Restrict contradiction references to the same schedule enum and bind document_id/payload_sha256 by single-value enum. All global response sections remain unchanged. `wi70-response.schema.json` is the concrete reviewed70-key instance. Record, expanded payload and production/shared schemas remain unchanged.

Reject duplicate raw JSON keys at every depth before object construction, as well as malformed/trailing JSON and nonstandard numeric constants. A permissive last-key-wins parser erases evidence of invalid duplicate IDs before schema validation and is forbidden. After strict parsing and keyed schema validation only, normalize each sorted expected key into the existing assessment row by adding item_id, preserving its fields, and changing only the wire schema tag back to round7.record_verdict.v1. Then run the existing host exact-set/uniqueness, binding, evidence and consistency checks. This is lossless normalization, not removal of extra rows or repair. All metadata hashes identify both exact wire body and original expanded payload. Input ID collisions remain preflight errors.

Design comparison: array enum+fixed count is smaller to implement and retains the old wire shape, but still permits balanced duplicate/missing IDs in schema and delegates uniqueness to host rejection. A keyed object adds a small lossless adapter and a required strict parser, while its schema requires every ID and forbids extras. The chosen keyed design directly constrains both missing and extra entries. Neither proves semantic completeness. The array candidate and its10 fixtures are retained as comparison artifacts, not the active contract or a fallback. No provider compatibility is claimed; a schema rejection requires a stop and separate decision, not silent reversion.

Send a neutral explicit schedule instruction: every expected key once; coverage appears only in global sections. This is candidate-derived metadata, not source truth or a defect hint. Host diagnostics still report missing/extra/duplicate IDs where available (duplicates are raw-parse failures). Do not trim unknown keys, accept a subset, retry, or continue malformed output. Do not assume every structured-output provider supports wide required objects until separately authorized testing.

Use the existing global `completeness` and `missing_items` sections. The completeness reason must assess record.coverage as a claim and explain source omissions independently; it must not cite claimed_complete as proof. A missing source fact need not have a candidate item ID. No new coverage assessment row/property is introduced. A reviewer may judge this reason inadequate; schema acceptance alone cannot enforce the meaning of that text.

## Independent semantic boundary

There are two universes: candidate record IDs determine response membership; source units determine completeness. Never derive the latter from candidate items or model omissions. For real research, source-only image review freezes the complete participation universe, scope and uncertainty before outputs. An independent postrun audit enumerates every candidate claim and maps every frozen source unit, preserving unknowns and unsupported additions. Existing R8 mapping remains unchanged; fixture expected annotations are private evaluator inputs and not new R8 labels.

An exact evidence quote establishes where a proposition was printed. Recovery also requires an operative normalized assertion with value, role, modality, applicability and required relationship endpoints. Source_text, evidence_table, evidence quote strings and coverage.rationale cannot supply a missing normalized assertion. Existing semantic fields such as event.description or identity.literal may assert a rule transition; no new record property is needed. Equivalent supported wording is acceptable after independent review; no requirement for one hardcoded string or keyword detector.

All required route endpoints must be matched before their relationship can match. A phone-only subgroup may be locally correct while the source's full Zoom/phone alternative group is incomplete. Co-listing and shared evidence do not prove interchangeability. Preserve group purpose and qualifications. The bounded fixture uses the existing single alternative_group_id representation and does not invent nesting semantics or change schemas.

If modality is unclear, association uncertain, or required channel/identity unresolved, do not call that field preserved or the whole record complete. A conservative unknown remains unknown; it is neither an automatic false fact nor a successful recovery. Retain source-conditional statements without inventing deadlines. Quantitatively unspecified timing is not necessarily source incompleteness. Complete eligible means the independent audit has complete source scope, all source units matched, all candidate claims supported and no unresolved acceptance guard. Unknown/unfinished/missing audit yields review and unavailable complete-support conclusion, never a default positive. Production/action flags remain false even for positive synthetic fixtures.

The existing I/l image-reference ambiguity and supplementary PDF evidence stay separate. No original label is repaired. Unambiguous synthetic endpoints isolate the three intended regressions without pretending to improve real-source accuracy.

## Fixtures and their meaning

`development-fixtures.json` contains complete synthetic sources, existing-shape records, source-first expected units and variant dispositions. Rule assertion: positive event description versus evidence-only negative; a coverage-rationale copy must not repair it; a source-only added comment phase/deadline must be detected despite an unchanged candidate schedule. Alternatives: full3-route group versus phone subgroup, plus unknown endpoint closure. Modality: explicit optional source with optional, unclear and mandatory candidate variants. The positive controls prevent a checker that rejects everything from satisfying the suite.

Source units and expected outcomes are manually authored research annotations awaiting independent review, not independently proven gold. The implementation may use them to test aggregation/guard behavior and compare a future verifier response. Passing those tests proves only adherence to these examples. It cannot show automated discovery of arbitrary omissions. Do not implement a string/ID lookup that returns the fixture expected label and call that semantic validation. Do not present expected outputs as measured model results.

`response-fixtures.json` is a separate syntactic suite. Its positive controls have uncertain judgments and must still review. It tests exact keyed membership, member-order permutation, missing/extra keys, duplicate raw keys at assessment/nested/top levels, forbidden embedded item_id, document/payload binding, contradiction references and complete-with-missing inconsistency. Global coverage therefore remains auditable while outside the per-item ID namespace.

## Leakage and review barrier

Only a selected source, candidate record, candidate-derived ID schedule and neutral frozen instructions/schema may enter a future provider request. Never serialize fixture expected fields, source-unit oracle, sibling variants, prior defects/audit text, reviewer verdicts or failure-specific coaching for that notice. Development authors have seen prior failures; these cases are not held out. Any later model diagnostic on these cases must say development reuse. New accuracy work requires separately authorized source selection, preregistration and independent reference freeze.

Barrier deliverable: primary/reviewer checks source assertions, minimal-pair changes, expected unknown handling, exact schema scope and leakage controls; resolves ambiguities before freezing implementation inputs. Implementation may then add bounded request-schema generation, host diagnostics and fixture/test harness in a separately assigned NEW area. It must consume independently adjudicated source mappings for semantic aggregation, not derive them from a candidate verdict. If source mappings are unavailable, it can validate syntax and say semantics unverified, not invent a completeness decision.

Acceptance obligations are enumerated in TEST-OBLIGATIONS.json. Authoring integrity checked only JSON record shape, offsets/hashes and schedule uniqueness; implementation tests and semantic/model evaluation have not run. No paid release follows this review automatically. No installs/builds or production/shared-contract edits are authorized here.

Each synthetic variant now includes an explicit private oracle_mapping: source-unit ID, expected disposition, actual semantic record pointers, required endpoint-unit IDs and manual provenance. These mappings are proposed reviewer inputs, not independently measured truth. The source-only omission control has empty record pointers, demonstrating that source obligations can exist with no candidate item. Pointer resolution is authoring integrity, not semantic proof.

## Compact schema and unchanged input guard

The active WI schema now uses exactly two local definitions: `$defs.a` is the shared assessment value and `$defs.e` the shared evidence array. Assessment keys remain explicitly required and extra keys forbidden. Expanding these refs reproduces the preceding full schema exactly; no semantic constraint was removed. `wire-size-check.json` records the prior expanded canonical hash and the compact comparison. The measured offline request fixture preserves the old user message and evidence-table payload exactly and appends only a neutral wire instruction; the ID list is not redundantly serialized in prose.

The compact schema is 7,506 canonical UTF-8 bytes. The complete request is 38,432 bytes; with the unchanged 1,024-byte allowance it is 39,456, leaving 544 under the unchanged 40,000-byte guard. These are offline byte measurements, not provider acceptance or token forecasts. The exact measured request is `wi70-offline-request.fixture.json`; it was not sent. Any changed request must be remeasured and fail closed when over guard.

Before local schema validation, the implementation must explicitly resolve only singleton reference objects `{"$ref":"#/$defs/a"}` and `{"$ref":"#/$defs/e"}` against the exact checked-in definitions. Reject external/unrecognized/missing references, reference siblings, cycles or nesting above8; never ignore `$ref` in the old validator. This is a bounded local expansion, not a general remote schema loader. After expansion, validate all existing constraints with the old validator; send the compact form in the provider request. The resolver and its negative tests are implementation obligations, not implemented here. Provider support for local references remains unverified and a provider rejection must stop without schema fallback, retry or guard inflation.
