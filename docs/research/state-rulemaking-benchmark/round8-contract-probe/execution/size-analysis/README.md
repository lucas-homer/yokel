# Full-request size diagnosis and lossless offline prototypes

The actual normalized record is retained, but both verifier bodies fail their current guards: stronger estimate 40,553 exceeds 40,000 by 553; Jev state plus longest question 33,149 exceeds 32,000 by 1,149. Jev's full request estimate 40,604 is below its 64,000 total guard. Neither verifier was called. These estimates are canonical UTF-8 JSON bytes plus a 1,024 allowance, not actual provider tokens, model context usage, or invoices. A longer record can fail even with unchanged source and prompts.

The common payload is 29,889 bytes: record 25,763, source-text field contribution 3,685, and other identity/hash/review/schema fields plus punctuation. Within the record, routes contribute 10,225 bytes and requirements 6,950 (including their evidence and claims), events 3,684, uncertainties 1,833, alternative groups 1,288, coverage 814 and identities 797. Additive field accounting with exact punctuation is in REPORT.json. The full source remains in both arms and is not the dominant cost.

There are 81 resolved evidence occurrences but only 42 unique evidence objects/quote strings. Evidence arrays occupy 11,047 bytes (about 43% of the record). Their evidence objects occupy 10,895 bytes, with 8,179 bytes in JSON quote values. Unique objects occupy 5,782 bytes and unique quote values 4,378. Repeated quote values therefore account for 3,801 bytes beyond their first copies, before repeated span/key/punctuation costs. These repeats represent evidence belonging to different claims; deleting the associations would lose information. The prototypes retain every occurrence in its original array position.

Stronger overhead includes 4,124 bytes for response_format, 2,515 for the system-content JSON string, and 2,584 additional bytes from embedding the 29,985-byte user JSON as an escaped message string. Jev's five questions occupy 9,647 bytes. Their common instruction prefix is 1,113 bytes repeated five times (4,452 repeated bytes beyond the first). The prototype retains all five copies: moving common instructions into shared state would require separate provider and semantic validation, and would not by itself shrink Jev's state-plus-longest constraint. The measurements do not assume an API supports a new shared-instruction mechanism.

Three diagnostic wire encodings were measured with explicit decoding instructions included once in stronger's system content and in all five Jev questions. They preserve full source, every record field/claim/association/uncertainty, all evidence occurrences/order and exact original hashes. All restore the canonical common payload and both full original serialized request bodies exactly. New decoding instructions are removed only during the explicit diagnostic restoration; nothing is silently omitted from the measured candidate bodies.

All three fit the current 40,000 stronger, 64,000 Jev total and 32,000 Jev state guards mechanically. The exact-quote table has 4,245 stronger and 3,292 Jev state units of headroom, after its 406-byte decoding instruction is included in each required placement. Span-only versions save more, but require model substring retrieval using Unicode codepoint offsets. That is materially different from reading supplied exact quotes; round-trip reconstruction in Python does not establish that a model can count offsets or retrieve evidence correctly. Keep the exact quotes visible in a first experiment rather than assuming offset-only equivalence at inference time.

The files named DIAGNOSTIC-*-wire-payload.json are unobserved development encodings, not observed provider requests or schema-valid R7 records. No existing schema, runtime, request, paid artifact or provider contract was changed. “Provider compatible” is explicitly false in the report: compatibility is unverified and a separately versioned wire contract plus new reviewed serializers/instructions would be needed. The response schema and original record validation could remain unchanged after deterministic restoration, but this has not been implemented as a live path. Wire encoding changes model presentation even when information is losslessly recoverable.

Eleven offline controls pass: actual full bodies round-trip exactly for all encodings; repeated equal text at distinct spans and Unicode codepoint offsets reconstruct correctly; source-hash changes, invalid references/spans and changed exact table quotes reject; reassociating a valid reference changes the restored original payload hash and is detected by the required comparison. A valid but misplaced table reference is not intrinsically invalid: a future decoder must bind and verify the original canonical payload hash, not merely bounds-check its index. Full-payload equality proves preservation of every claim and association for this case, not semantic truth or model judgment equivalence.
