# R8 durable live adapter plan / interface

Scope: runtime/ and execution/service-account/ code only; primary owns collection, policy, authorization, build and live dispatch. Prior rounds immutable. No future labels are semantically read. Preparation/testing uses mock native provider bytes only.

1. Hash-pin read-only R7 pipeline/schema, exact-request, parser and strict observed semantics. Retain round7 inventory/record/verdict/payload IDs; emit new round8 runtime/code/authorization receipts. No simulation is used for live dispatch.
2. Adapt R6 append-only fsynced operation ledger locally: identical-byte completed resume only; durable intent precedes a single POST; uncertain/HTTP/invalid/usage failure latches stop; no retry, fallback, repair or clipping. Fixed total budget=2, <=24 new operations, <=8 each inventory/Jev/stronger, <=8 notices and <=40 actual PDF pages.
3. `code_pins()` / `--prepare-implementation PATH` creates code-only implementation.json before collection. `run(manifest,source_root,freeze,out,live=False,...)` validates and hashes sources without credentials. Manifest uses round8.sources.v1 with R6 strict document fields: document_id,channel,text_path,text_sha256,pdf_path,pdf_sha256,pdf_pages,scope,native_page_map_known. Sources are full native notice text; structural invalidity remains an honest per-document gate.
4. Live authorization shape: round8.live-authorization.v1, implementation_sha256,manifest_sha256,source_labels_frozen_before_outputs=true,source_labels_freeze_sha256,nominal_budget_usd=2.0. Primary supplies final code/source/label freezes before execution. Runner checks the label-freeze hash binding only; never loads labels.
5. `requests` uses frozen R7 final serializer/admission. Both verifier bodies must admit and their inner full-source+record payloads match before either arm operation. Components/groups all assessed. Jev native Choice probabilities/abstention parser remains distinct from stronger generative schema. Coverage means validated full schedule, independent of positive judgment.
6. terminal/observed artifacts preserve R7 strict called/uncalled and retained-judgment consistency. Structural/source/size gates continue denominator. Successfully parsed postresponse cost overruns preserve paid inventory/arm results at postresponse_budget_stop and stop subsequent calls; the runner audits receipts against durable ledger facts. Actual inventory/provider failures emit evidence-hash-bound operational receipts; provider_service_error means confirmed non-200 HTTP status only. Uncertain transport and invalid output are distinct causes. Safe no-intent pauses use operation_pause; later documents stay not_started. Failures emit honest metadata and stop the run; later documents remain explicitly not started. Completed records never set action_ready or production_eligible. No invented judgment/hash to satisfy schemas.
7. Service-account code accepts only fixed check/live-initial entry points; binding.json/dependencies.json/native-job.json are generated later by primary. No credentials during check/pinning. Native isolated -I -S -B entry reads keys from approved injected environment only after binding/code/source checks; no Keychain/op lookup/enrollment inside Python. Native v3 policy/build/Keychain authorization is outside this child.

Offline acceptance: paired byte identity; source-only inventory; budget and per-stage caps before POST; complete resume avoids duplicate POST; uncertain POST cannot resume; response/hash/identity/usage tamper stops; both-request admission with no partial calls; positive/negative/full/invalid assessments; actual failure invocation states; <=8 notice/40 actual pages; source/implementation/auth drift; check path no environment read. Tests and code-only receipt precede any release for live.

Protocol entry: round8/protocol/evaluate.py::validate_observed. Every document requires nullable failure; causes and evidence hashes follow CONTRACT.json. Failure evidence points to a retained failure/pause receipt binding intent/status/stop hashes.
