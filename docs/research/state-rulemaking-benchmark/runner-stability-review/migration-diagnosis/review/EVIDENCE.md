Apple's SecKeychainItemSetAccess implementation invokes setAccess with update=true; the Access implementation iterates its ACL objects and skips unchanged entries in update mode. This explains why creating a new access object did not replace every effective entry. A copied partition entry retains its existing identity and can be targeted as an update. Sources: https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_keychain/lib/SecKeychainItem.cpp and https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_keychain/lib/Access.cpp . SecACL.cpp specifically routes the hex description of integrity-form entries into their payload; ACL.cpp maps partition subjects to that form. This supports preserving the subject type when using SecACLSetContents on an existing partition entry, instead of constructing an allow-all entry: https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_keychain/lib/SecACL.cpp and https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_keychain/lib/ACL.cpp .
