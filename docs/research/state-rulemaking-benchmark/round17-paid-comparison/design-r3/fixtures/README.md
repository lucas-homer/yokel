# R17 scoring fixtures (design r3)

All sources, references and outputs here are **fictional**, except F21. F21 pins the frozen R15 fictional control (`round15-condition-preservation/protocol-revised/fixtures/{source.txt,expanded.json}`) by SHA-256 to prove that the scorer reads a real r16 expanded record. Expected judgments were written by hand from ADJUDICATION-SPEC.md, not generated by the scorer. No R17 source text was read to write them.

| File | Role |
|---|---|
| `cases.src.json` | Authored cases. Quotes are `[text, occurrence]`. |
| `cases.json` | Built form, with every quote resolved to explicit `start`/`end`/`occurrence` and each case's opaque packet id and binding hashes. `check.py` refuses to run if it is stale. |
| `r17score.py` | The mechanical scorer (ADJUDICATION-SPEC Part B), `validate-reference` (E4), and `decide`, the only decision entry point (C5). |
| `r17recon.py` | Reference semantics for ledger admission, debits, cumulative key-usage reconciliation and run-close retention (BUDGET §4–§5). Pure functions; no I/O. |
| `check.py` | The checker. It rebuilds, validates and scores every case, and runs the invalid-reference, canonical-example, decision, ledger, `decide` assembly and gate self-test fixtures. It also emits the blind adjudicator packets and runs the P5 adjudicator gate. |

```sh
python3 -I -S -B check.py                       # exit 0 = every expectation holds
python3 -I -S -B check.py --write               # rebuild cases.json after editing cases.src.json
python3 -I -S -B check.py --emit-packets DIR    # one opaque packet per gold case (Part A, source, reference, output, bindings)
python3 -I -S -B check.py --adjudications DIR   # P5: DIR/A1/<packet>.json and DIR/A2/<packet>.json, both required
python3 -I -S -B r17score.py validate-reference REF.json parsed-body.txt
python3 -I -S -B r17score.py decide DECISION.json [--interim]
```

`check.py` prints scorer-check counts by section and, separately, the adjudicator-gate result. Without `--adjudications` the gate is reported as "not run"; P5 is not met until both A1 and A2 pass it.

**Gold vs mutation.** `gold: true` cases are adjudicator gold packets: every unit has `assertion` and `evidence`, every gold mapping obeys M2, and identical packets have one gold mapping (all checked). `gold: false` cases (F05b) supply a deliberately wrong mapping to test the scorer and are never shown to an adjudicator. Packets carry an opaque id (`fx-…`) and an opaque `source_id`, never the case name, purpose, expectations or mapping.
