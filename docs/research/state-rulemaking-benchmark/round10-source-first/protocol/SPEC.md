## Stage A boundary and inventory semantics

Only stage-a.system.txt, the source-bound stage-a.schema.json, request-settings.json and user JSON {source_text, source_text_sha256} enter A. Source hash is calculated from exact UTF-8 text. No record, record IDs or hints, prior inventory, labels, audits, defects, prior outputs, document-specific guidance or semantic metadata may be accessed by the A builder. The offline request is an exact candidate, not dispatched. For synthetic tests bind source hash dynamically using the selected source only. The full source is immutable; no substring selection or normalization.

Inventory means assertions whose loss changes understanding or participation: facts, identities, instructions, policies, relationships, roles, modality and applicability. It is not limited to legal mandates. Split independently lossy assertions. Relations identify their complete endpoint set through required_unit_ids, with purpose and qualifications in assertion/applicability. Endpoints are separate units; dependencies are acyclic. Conditional force must state the condition and the force within it in assertion/applicability. Do not invent a quantitative deadline for an unquantified instruction.

Hard bounds: 1–64 units, unique u001–u064 IDs (gaps allowed; no renumbering), at most 16 dependencies and 3 evidence selectors per unit, and field bounds in schema. Bounds constrain the experiment, not the source universe. If an otherwise valid response leaves source material out to fit, independent review must record the omission; host syntax cannot detect that omission. A refusals/overflow/truncation/non-stop finish or invalid response stops the run, with no repair, clipping, retries or fallback. No overflow marker is accepted as a successful inventory.

Each evidence selector has a nonempty exact contiguous quote and 1-based occurrence. Enumerate all exact occurrences at Unicode codepoint starting positions, including overlapping occurrences; choose the specified index. Reject unavailable occurrence or mismatched characters. Do not normalize whitespace, punctuation, OCR glyphs or Unicode. Derive start/end offsets host-side only for review; preserve raw response and original selector. Empty/whitespace-only assertions, applicability, reasons where required, and quotes are invalid. uncertainty_reason is empty iff uncertainty=none. Unknown modality or source ambiguity stays scoped to affected units and dependent relations.

Strictly parse raw JSON before constructing objects: reject duplicates at every depth, trailing/malformed JSON, nonfinite constants and exponent overflow. Validate closed schema, source binding, all bounds, IDs, evidence and dependencies. Reuse reviewed strict parsing and schema machinery, extending the bounded local-ref allowlist explicitly to e/u/m with no external refs, siblings, cycles or ignored keywords. Existing resolver only accepts its old definitions; do not call it unchanged and pretend these new schemas were checked. Provider compatibility remains unverified. No silent schema downgrade.

Freeze A raw response bytes, parsed canonical inventory bytes and both SHA256 hashes plus request/response receipts before constructing B. Canonical JSON is ensure_ascii=false, sorted keys, separators comma/colon, allow_nan=false, UTF-8. Record provenance includes model/provider identity, request hash, finish reason, usage, validation report, source hash and all protocol/runtime pins. Neither canonicalization nor offset derivation alters claims or repairs output. A model inventory never becomes an independent source reference merely because it validates.
